### Honest limits and remaining acceptance

Owner-approved scene look/feel is carried forward from the editable keyframe. It is cleaner and more regular than the original atmospheric laboratory concept; no claim of pixel or painterly equivalence. Foreground is deliberately behind actors so it cannot conceal character/contact/exit. The wider resting silhouette uses camera/wall/floor overscan rather than changing player bounds. Original low sliding blob and box/chair silhouettes remain the mechanics POC's simple presentation; no extra animation sets were commissioned. Standing/stagger holds an existing guard pose and defeat uses the existing simple rotated-frame approach, not a new death animation. These are final visual-review subjects.

The peak tip maps to 105 units **from the actor origin**, matching the engine's center-distance predicate. It is not a pixel hitbox or a new contact model for the guard's visible body width. Damage and immediate defeat still occur on input, before peak visual extension (~100 ms). The body contraction remains provisional. Evidence shows the timing honestly; no mechanical changes or delayed reactions were used to conceal it. If the owner requires physical blade-contact timing, return to a bounded presentation/timing Offer before altering accepted schedules or rules.

Final scene/character-scale coherence, actual camera clue readability across the route, simplified remaining forms and contact treatment await owner acceptance. No autonomous next stage is authorized. Technical checks establish current functionality, not artistic approval or release readiness. Project lesson: keep source art frozen, quantify scale and compositing differences, and run stable-build reload tests when introducing asset preload. No shared-standard change proposed.
